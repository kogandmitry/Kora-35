# КОРА 35 — правило синхронизации двух мониторов

**Принято:** 19 июля 2026 года  
**Владелец правила:** Дмитрий Коган  
**Исполнители:** Codex и другие ИИ-агенты проекта

## Постоянные версии

- Орггруппа: `https://eliseyyauezhik.github.io/Kora-35/org/`
- Заказчики: `https://eliseyyauezhik.github.io/Kora-35/customer/`
- Точка выбора: `https://eliseyyauezhik.github.io/Kora-35/`

Эти адреса считаются постоянными. Обновляется содержимое, а не URL.

## Обязательное правило

Как только в проектных файлах подтверждённо меняются задачи, решения, риски, сроки, ответственные, бюджет или информация, необходимая получателям, соответствующее изменение сразу отражается в мониторе в рамках той же работы.

Работа не считается завершённой, пока не выполнены четыре действия:

1. обновлён профильный источник проекта;
2. обновлены данные соответствующей версии монитора;
3. пройдены тесты и проверены обе аудитории;
4. обновление опубликовано по постоянным ссылкам либо явно зафиксирован блокер публикации.

## Разделение аудиторий

| Информация | Орггруппа | Заказчики |
|---|---|---|
| Конкретные задачи, владельцы и сроки | полностью | только контрольные точки и задачи, требующие решения заказчиков |
| Следующие действия и запросы КП | полностью | агрегированно |
| Риски и меры снижения | операционно | ключевые управленческие риски |
| Бюджет | построчно, статусы цен, владельцы | сценарии, блоки, резерв, превышение/запас |
| Решения | все рабочие решения | утверждённые решения и открытые вопросы для заказчиков |
| Источники | рабочая свежесть и происхождение | краткая дата актуальности |
| Закрытый контур | запрещён | запрещён |

## Технический порядок обновления

1. Сверить свежие источники проекта и `CHANGELOG.md`.
2. Обновить `data/kora35-monitor.json`.
3. При изменении бюджета обновить `data/kora35-budget.json`; для импорта канонического артефакта использовать `npm run import:budget -- --input <artifact.json>`.
4. Обновить `project.lastUpdated`, источник и запись в `updates`.
5. Выполнить `npm test` и `npm run validate`.
6. Проверить `/org/` и `/customer/` на широком и узком экране.
7. Опубликовать и проверить живые URL.

## Граница публикации

GitHub Pages не является защищённым внутренним контуром. Рабочая версия орггруппы на этой платформе может содержать только безопасную операционную информацию. Для конфиденциальных данных нужен отдельный сайт с авторизацией на VPS.

Если GitHub недоступен для записи, локальное обновление сохраняется, в задачах создаётся блокер публикации, а пользователю сообщается, что постоянные ссылки ещё показывают прежнюю версию.
